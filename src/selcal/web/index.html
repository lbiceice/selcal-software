Saved reports and evidence

No artifact requested in this view.

Files are named selcal-<job>-<operation>-report.html (readable report), …-result.sqlite (the verifiable record for selcal verify; not a spreadsheet) and …-evidence.zip (eleven checked files, including the summary.csv, candidates.csv and replicates.csv tables that open in a spreadsheet). The server re-checks each saved artifact and states its size and SHA-256; this page checks the received size, and the SHA-256 where the browser provides Web Crypto (otherwise the status says only the size was checked), before handing the file to the browser. With no download manager installed, the browser saves it under its own settings, usually its default download folder; if a download manager such as IDM is installed, it may take over and save elsewhere. Only the browser's downloads list, or the manager's completed list, shows whether and where it was saved. The status line also names the checked original inside the workspace folder, which can be copied without any download.

Reports and eleven-file evidence exports check recorded content without replay or authenticating historical execution. Every download checks the saved input, plan, record and artifact again. Availability alone is not verification. The ZIP is a transport copy of the checked eleven files, not a new scientific format.

What this result means

Circular-shift calibration requires a defensible circular exchangeability assumption; block shuffle requires exchangeable blocks with an appropriate block length. Prespecify the candidate family and parameters for your data. Selecting a lag does not establish causality. A non-rejection does not show there is no association.

NOT_EVALUABLE means the configured procedure could not supply an evaluable result. It is not p = 1, not non-significance, and not an operational failure. Read its precise failure stage.

Resume requires the original code and environment and a valid checkpoint. Interrupted initialization may not leave a recoverable checkpoint. Older jobs without an explicit saved-record reference can use command-line verify, report and export; the UI never guesses old result paths. Final integration, wider usability and release validation remain pending.
